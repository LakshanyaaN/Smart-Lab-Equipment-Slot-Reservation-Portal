# Lab 5 – Static Code Analysis
## Reflection

### 1. What is the importance of static code analysis in software development?

Static code analysis helps identify potential programming errors, security vulnerabilities, and coding style violations without executing the program. It improves code quality, reduces debugging time, and makes software easier to maintain. Tools such as Pylint, Bandit, and Flake8 help developers identify problems early in the development process.

### 2. What did you learn from using Pylint, Bandit, and Flake8?

I learned that each tool serves a different purpose.

- **Pylint:** Checks Python code quality, detects programming mistakes, and identifies issues related to naming conventions and code structure.
- **Bandit:** Identifies common security vulnerabilities and unsafe coding practices.
- **Flake8:** Checks Python code formatting and compliance with PEP 8 coding standards.

Using all three tools provided a better understanding of different aspects of code quality.

### 3. What were some of the major issues identified in your program?

Some major issues identified in the Employee Payroll System included mutable default arguments, unsafe use of `eval()`, weak MD5 hashing, insecure random token generation, unsafe shell execution, and hardcoded secrets.

These issues could affect the security, reliability, and maintainability of the application.

### 4. How did you resolve the identified issues?

I modified the program by replacing mutable default arguments with `None`, removing unsafe `eval()` usage, replacing MD5 with SHA-256, using the `secrets` module for token generation, and removing unsafe shell execution and hardcoded secrets.

I also improved exception handling, formatting, and naming conventions.

### 5. How did static code analysis improve your program?

Static code analysis helped improve the overall quality and security of the program. After making the required changes, the Pylint score increased from 5.32/10 to 10.00/10. Bandit reported no security issues, and Flake8 reported no formatting errors.

This demonstrated how static analysis tools can help produce cleaner and more reliable code.

### 6. What challenges did you face during this lab?

One of the main challenges was understanding the warnings generated by different static analysis tools and determining the appropriate fixes. Some issues required changes to the program's logic, while others involved improving security practices and formatting.

Running the tools again after making changes helped verify that the issues had been resolved.

### 7. What did you learn from this lab?

This lab helped me understand the importance of writing secure, clean, and maintainable Python code. I learned how to use Pylint, Bandit, and Flake8 to identify different types of issues and how to fix them.

I also understood that static code analysis should be an important part of the software development process because it helps detect potential problems early.
